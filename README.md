# CivicAI

AI-powered civic infrastructure monitoring for safer, more accountable
communities.

CivicAI uses computer vision to identify and document infrastructure issues
from vehicle or mobile-camera footage. The initial focus is pothole detection,
with the architecture designed to support additional civic infrastructure
categories over time.

## Project status

The repository contains a YOLO-based pothole detection/tracking path and a
SQLite-backed dashboard API. The reporting layer now supports timestamped GPS
fix association, tracker-level incident aggregation, evidence-context assembly,
and optional LLM-generated incident/area narratives. The LLM provider must be
configured locally before narrative generation is available.

## How it works

```text
Camera or video stream
          |
          v
Frame acquisition and preprocessing
          |
          v
Pothole detection
          |
          v
Object tracking and validation
          |
          v
Evidence crop storage
          |
          v
SQLite database
          |
          v
Reports and dashboard
```

Each validated observation is intended to include:

- Issue category and detection confidence
- Timestamp and tracking information
- GPS coordinates and reported accuracy when a timestamp-matched fix is available
- GPS source and simulated-data flag
- A reference to the captured visual evidence
- Frame timestamp and GPS association method

## Getting started

### Prerequisites

- Python 3.10 or newer
- Git
- A virtual environment

### Setup

From the project root:

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

The dependency file is currently a placeholder while the backend modules are
being implemented. Add runtime dependencies there before running the
application.

### Run the dashboard

Install the backend dependencies, start the API, and start the dashboard in
separate terminals:

```powershell
cd backend
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run_api.py
```

```powershell
cd dashboard
npm install
npm run dev
```

The dashboard reads persisted backend records from `GET /api/potholes`.
Detection crops are stored as image BLOBs and served by
`GET /api/potholes/{id}/image`. GPS appears only when timestamped fixes have
been imported for the same session and the recording start time is known.
Synthetic coordinates remain explicitly marked as simulated. Incident reports
are generated by `POST /api/incidents/{id}/report`; area reports use
`POST /api/reports/area`.

### Configuration

Copy `backend/.env.example` to `backend/.env`. Never commit API keys.
For prerecorded video, set `CIVICAI_RECORDING_START_TIME` to the real
recording start time in ISO-8601 format with a timezone. Set
`CIVICAI_SESSION_ID` to a stable ID shared by the video run and GPS import.
If the start time is unknown, GPS will not be attached to those video frames.

GPS CSV files require `recorded_at,latitude,longitude,accuracy_m`, with
timezone-aware ISO-8601 timestamps. Import fixes from the backend directory:

```powershell
python import_gps.py --session-id your-session-id --csv path\to\gps.csv --source synthetic --simulated
```

For real device fixes, use `--source gps` without `--simulated`. Synthetic
coordinates must always use both `--source synthetic` and `--simulated`.

Configure an OpenAI-compatible chat-completions endpoint with
`CIVICAI_LLM_BASE_URL`, `CIVICAI_LLM_API_KEY`, and `CIVICAI_LLM_MODEL`.
Without these values, report endpoints return HTTP 503 rather than fabricating
an LLM response. The local database is stored at `backend/data/civicai.db`,
and evidence crops are stored under `backend/storage/potholes/`.

## Development workflow

1. Add or update a backend module under `backend/app/`.
2. Keep model files in `backend/models/`.
3. Store generated evidence under `backend/storage/`.
4. Persist structured detection data in SQLite.
5. Add tests alongside the feature before integrating it into the detection
   workflow.

## Planned capabilities

- Video and live camera stream ingestion
- Pothole detection and multi-frame tracking
- Live GPS-device ingestion and camera-to-road coordinate correction
- Cross-session duplicate matching after reliable defect coordinates exist
- Evidence image management and interactive map improvements
- LLM-assisted reports from persisted, traceable database records
- Additional monitoring modules for footpaths, waste, road markings, and signs

## Responsible use

CivicAI is intended to support infrastructure inspection and prioritization.
Model predictions should be reviewed and validated before being used for
official decisions. Detection confidence is an indicator, not proof that an
issue exists.
